## 2. 语音对话与课堂轮流机制

### 当前链路图
```
Client录音 → AUDIO_CHUNK_BIN → WebSocket → 缓冲 → VAD检测
  → SeamlessM4T ASR (asyncio.to_thread, CPU/GPU)
  → 持久化 USER_MESSAGE → 组装history → LLM调用(Kimi/Qwen竞速)
  → 持久化 AI_MESSAGE → TTS合成(Kokoro/Edge-TTS/Silence)
  → TTS_CHUNK推送(前端静音缓冲，不播放) → TTS_RESULT全量音频 → Client播放(非真流式)
```

### 已完成的发现
- **一轮对话步骤**: 17步 (录音→VAD→ASR→LLM→TTS→播放)
- **CPU/GPU消耗**: ASR (SeamlessM4T CPU推理)、TTS (Kokoro CPU推理)、LLM (Kimi API网络+GPU)
- **上下文管理**: 按 conversation_id 管，不按 user_id/class_id/lesson_id 管
- **无课堂级 turn-taking**: 无 teacher_pick、student_queue、current_speaker、旁听机制
- **TTS 非流式**: 后端发送 `TTS_CHUNK` 但前端仅做静音缓冲（不播放），等 `TTS_RESULT` 全量音频到达后一次播放。见 `voice.ts:208-222` 注释 "We do NOT play them; full audio arrives via TTS_RESULT"。当前不是真流式。
- **前端播放**: `audio-manager.ts` playWavChunk() 顺序播放，有队列管理
- **限流/排队/超时/取消/重试**: 均无
- **上下文串号**: 多人轮流练时如果都用同一个 conversation_id 会串

### 部署建议
- WebSocket 连接数 = 并发练人数 (<10可接受)
- ASR 需加 thread pool 限制，避免 30 人同时 ASR 撑满 CPU
- Kimi API 并发调用有 QPS 限制，需排队
- 建议引入 classroom_session_id 隔离不同课堂的上下文

## 3. 上下文管理、存档、恢复、模型调用

### 当前机制
- **两条独立路径**:
  - WS 语音管线 (`/ws/v1`): 所有事件持久化到 SQLite `conversation_events` 表，按 conversation_id 查询
  - `model_router.py` 的 `ConversationContext`: 内存中独立子系统，含摘要压缩、滑动窗口、记忆点，但 WS 管线不使用此子系统
  - `context_store.py`: 死代码
- **重连恢复**: 靠 last_seq 参数断点续传
- **历史组装**: `get_all_chat_history_from_events()` 按 conversation_id + 事件类型查询，不按 user_id/session_id 过滤
- **CONTEXT_SET 事件**: 可在连接后更新 session_user_id，但 conversation_id 不变时上下文混合

### 会串的场景
1. 两个学生共用 conversation_id → 历史混合
2. 教师切换学生但不换 conversation_id → 新旧上下文混合
3. 同一学生多个课堂/任务 → 一个 conversation_id 平铺所有事件
4. 重连后 last_seq 从某个值开始，但之前的历史已混乱

### 建议
- SQLite 仍可作主存储，但需引入 `session_id + task_id + user_id` 三维索引
- Kimi API: 需在每次调用前手动组装历史的摘要版本（现已在做）
- 本地 vLLM fallback: 需抽象 `ContextBuilder` 接口，支持不同的历史组装策略
- ConversationContext 的摘要压缩逻辑可复用，但需迁移到 WS 管线

## 4. Web 课堂版可行性

### 可行性结论: 可行但有三个阻断点

**阻断点**:
1. **npm build 失败**: `voice.ts` 函数缺少闭合 `}` (第 452 行只关闭了 if/else，startCustomSession 函数体未关闭)

- 麦克风 API: `audio-manager.ts:38` 纯 Web 标准 getUserMedia()

- `config.ts:146/172`: getConfig/setConfig 有 localStorage 回退
- `audio-manager.ts:366`: asr.transcribeFromBase64 有回退

## 5. 查词、作文、学情分析数据闭环

### 数据流
**查词**: 前端 `vocabulary.ts` → `/v1/vocab/lookup` → `UserVocabQuery`(term/source/result/CEFR/difficulty) + `VocabularyItem`(mastery_level/next_review_at) + `LearningRecord`(type=vocabulary)

**作文**: `/v1/essays/grade` → `EssayResult`(dimensions.content/structure/language/grammar 0-10, total_score, grade, feedback, suggestions, corrected_text)

**语音对话**: WS → `conversation_events`(audio_duration_ms, word_count, response_latency_ms)

**学情分析**: 20维指标 (A1-A20):
- A01 词汇总量: 硬数据
- A02 词汇掌握率: 硬数据
- A03 新词学习量: 硬数据
- A04 CEFR 分布: 估算（元数据启发式）
- A05 作文数: 硬数据
- A06 平均分: 硬数据
- A07 分数趋势: 硬数据
- A08 语法错误频率: 估算
- A09 词汇多样性: 硬数据
- A10 作文长度: 硬数据
- A11 口语对话次数: 硬数据
- A12 口语平均长度: 硬数据
- A13 口语反应速度: 硬数据（response_latency_ms）
- A14 跨文化得体性: 估算（LLM 打分，不可用则 None）
- A15 发音可懂度: 代理
- A16 综合活跃度: 硬数据
- A17 连续学习天数: 硬数据
- A18 薄弱维度: 估算
- A19 提升最快维度: 硬数据
- A20 总体等级: 估算

**高风险**: 前端无页面连接 `teacherAnalytics.ts` 服务（定义在服务层却无对应视图组件）

### CSSCI 数据缺口
- 无数据导出 API (CSV/JSON)
- 无原始数据快照持久化
- 无 session 级时间戳对齐
- 估算指标缺乏人工评分校验基线
- 无实验组/对照组字段
- 无前测/后测数据模型
